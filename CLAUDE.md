# CLAUDE.md — cc-web-powerpack

Userscripts (Tampermonkey) that improve **Claude Code Web** (`claude.ai/code`).
Public repo: `brunompicinini/cc-web-powerpack`, default branch `main`.

## Workflow (publishing an update)
- **Edit the canonical local clone**, not stray copies: `~/Documents/GitHub/cc-web-powerpack` (the old "Web Empire" folder is retired).
- Edit the `.user.js` → **bump `@version`** → `git commit` + `git push` on `main`.
- Tampermonkey pulls from `raw.../main/...` on auto-update (checks once a day). To test right away: reinstall from the raw URL with a cache-buster `?cb=N`.

## Structure
- `scripts/*.user.js` — one userscript per file (filename ends in `.user.js`).
- `README.md` — installation (Tampermonkey + the Chrome 138+ "Allow User Scripts" toggle) and auto-update.
- `CLAUDE.md` — this file.

## Conventions
- Every script has a `// ==UserScript== ... ==/UserScript==` header.
- `@match https://claude.ai/code*`, `@run-at document-start`. `@grant`: favicon and shortcuts use `none`; **the notepad uses `GM_openInTab`** (to reliably open a link in a background tab — see below). With `@grant` != none the script runs in the Tampermonkey sandbox (DOM/`history`/`location`/`localStorage` are still real; it just can't see the page's JS vars).
- **Auto-update:** `@downloadURL` and `@updateURL` point at the raw URL on `main`:
  `https://raw.githubusercontent.com/brunompicinini/cc-web-powerpack/main/scripts/<file>.user.js`
- **Every published change requires bumping `@version`** — that's Tampermonkey's auto-update trigger.
- **Do NOT change `@name` between versions.** Tampermonkey uses `@name` (+`@namespace`) as the script's **identity**. If `@name` changes, a manual reinstall from the raw URL shows **"Install"** (a new/duplicate script) instead of **"Update"** — and the old one stays installed and keeps running alongside. Background auto-update updates in place even with a new name, but the documented "test right away" flow (reinstall from raw) breaks. So: new features go only in `@description` (free to change, TM doesn't match on it), **never** in `@name`. If you must change `@name`, accept that it becomes a reinstall + deleting the old one by hand.
- Filename and the tail of the raw URLs must match (otherwise auto-update breaks).
- Watch out for invisible characters used on purpose in regexes (zero-width `​-‍﻿` in the favicon; the notepad normalizes nbsp via ` `). Don't "clean them up" by accident.

## scripts/session-status-favicon.user.js
Recolors Claude's real favicon based on the open session's status and swaps the tab title for the session name.

Claude Code Web DOM facts (found by inspecting the page) that the script depends on:
- The session list is in `aside.dframe-sidebar`; each row is a `[data-row]`; the open one has `[data-selected]`.
- **Live status** comes from a `[role="status"]` inside the row, in its `aria-label`: `Running` / `Awaiting input` / `Ready`.
- **PR (merged/open)**: a session with a PR has **no `[role="status"]`** on the row — the state comes from a separate badge `[role="img"]` whose `aria-label` is `#21, #4 · Merged` (merged) or `#861 · Open` (open). `currentPR()` returns `'merged'` / `'open'` / `null`, filtering by `\bMerged\b` / `\bOpen\b` (merged wins — they don't coexist). Careful: other `[role="img"]` on the row are avatars (e.g. `Bruno Picinini`).
- The merged color (`#b796ff`) = Claude's native purple (`rgb(183,150,255)`). An open PR uses its own teal (`#2dd4bf`) — not the app's green (`rgb(50,215,75)`), on purpose, so it does **not** clash visually with the `running` green (`#22c55e`).
- **Priority: live status > PR (merged/open).** If the row has a live status it wins; it only falls to purple/teal when there's no status and the badge exists. (In practice they don't coexist, but if they ever did, running/awaiting is more useful to see.)
- The session name (editable header) is `button.cursor-text`.

Recoloring the favicon: it loads `claude.ai/favicon.ico` (same origin → the canvas isn't "tainted"), draws it on a canvas and uses `globalCompositeOperation = 'source-in'` to swap the color while keeping the shape. Each color is generated once and cached.

## scripts/session-notepad.user.js
Per-session notes side panel. Toggled by the injected action-bar button or by `Ctrl+Shift+S` (**the shortcut itself lives in `session-shortcuts.user.js`, which clicks that injected button** — see the cross-script hook below). `Esc` does **not** close it (on purpose, v2.22: Bruno uses `Esc` for other things and doesn't want the notes collapsing by accident — close via `×`, the button, or `Ctrl+Shift+S`). Resizable (width saved in `localStorage` key `cc-notes:w`, default 750px).

**Cross-script toggle hook:** the notepad injects its action-bar button with the attribute `[data-cc-notes-btn]`. `session-shortcuts.user.js` toggles the panel by doing `document.querySelector('[data-cc-notes-btn]')?.click()` — pure DOM, no cross-sandbox event. The notepad no longer has its own `keydown` listener. Trade-off: on the home page (no session, no action bar, no button) `Ctrl+Shift+S` is a no-op — acceptable, since notes are per-session and empty on home anyway.

**Floating panel (v2.24):** styled like the app's native panels (Background tasks etc.) — its own **elevated** background `rgb(38,38,38)` (the `surface-primary-elevated` token; **≠** `rgb(31,31,30)` of the body, which used to make the panel "stick" to the background with no contrast), rounded **8px** corners, a **9px** inset from the window edges (`top/right/bottom`, const `EDGE`) and a visible **12px** gap between the action bar/content and the panel (like the native one — see `RESERVE` below). No border and no shadow (like the native ones: the color contrast + insets already separate it). The `drawer` (fixed) is now just the **position/animation** container (transparent); the **`col`** is the visible card (background + `border-radius` + `overflow:hidden` to clip the editor at the corners). `squeeze()` reserves `w + RESERVE` in the content (`RESERVE = 8`, **measured** — v2.26) so the floating panel doesn't cover the content. **Why 8 and not 21:** the action bar (`⋮`, Share, Diff) has ~13px of its own padding inside `main`. Reserving `EDGE+12 = 21` (v2.24-2.25) made the bar follow the shrunken `main` edge **with** the 13px padding **and** the 12px gap, giving ~25px from bar→panel (Bruno noticed: much larger than the native one). Reserving just **8** (`w+8` on `main.right`), the content box sits **flush** with the panel and the bar's own padding becomes the gap — landing on **exactly 12px**, identical to the native one (which leaves `main` full-width under the panel and reflows via internal flex). Measured live against the native Background tasks panel (rightInset/topInset = 9, bar→panel gap = 12). **Slide-in/out:** uses the **same framer-motion spring as the app's native panels** (measured frame by frame in the app: `translateX 100%→0`, slow at the start, peak in the middle, long asymptotic tail). Reproduced **faithfully** with the CSS **`linear()`** easing (const `SPRING`, points = measured normalized progress), `SPRING_MS=300ms`. It is **not** a cubic-bezier (cubic-bezier can't reproduce the spring's tail). **Enter and exit use the SAME spring** (the native one is symmetric); on exit the slow tail happens **off-screen** (the panel has already left), so it *feels* faster — matching the perception of the native one. `transform: translateX(100%+24px)` (off-screen, to the right) → `0`. `display:none` only kicks in **after** the exit slide (via `closeT`, `SPRING_MS+60`). The open/closed state is the logical flag **`openState`** (not `display`), so `tick`/`squeeze` don't re-inject space during the exit slide. On close, `squeeze(false)` already returns the width to the content and the panel slides out **over** it (reveals the content with no "jump"). Slide-in detail: set `transition:none` + the initial `transform`, force reflow (`void drawer.offsetWidth`), then enable the transition and go to `translateX(0)`.

**Default template:** a session with no saved note opens with the template `# STATUS` / `# PRs` / `# CLICKUP` / `# LINKS` / `# NOTES` (const `TEMPLATE`, via `loadNote()` = `load(id) || TEMPLATE`). It's display-only — it doesn't write to `localStorage` until the user edits (the `input`/`blur` saves whatever is in the editor). An empty note (never saved or emptied) re-shows the template.

**Auto-open (per-mode layout):** a toggle in the header (switch next to the `×`), state in `localStorage` key `cc-notes:autostart` (`'1'`/`'0'`), **default on** (absence = on; only off if `'0'` is stored). When on, `applyMode()` adjusts the layout based on the URL:
- **In a session** (`/code/session_…`, there's a `sessionId`): opens the notes (via `setOpen(true, false)` — **without** focusing the editor, so it doesn't steal the page's focus) and **hides the sidebar** (collapses it).
- **On home** (`/code` with no session): **closes** the notes and **shows the sidebar**.

`applyMode` details: the **notes** only act on the *mode transition* (they don't reopen if you closed them on the same page). The **sidebar** is controlled by clicking the app's native button (goes through the handler — updates React + the persisted store), and applying it is *self-correcting*: it only marks it applied once the visible state already matches the desired one (if a click doesn't land, the next tick re-clicks). The manual toggle (`Ctrl+Shift+S`/button) still focuses the editor normally.

Sidebar DOM facts (native Cmd+B): the sidebar is `aside.dframe-sidebar` (open ≈280px, collapsed ≈28px). The state lives in the persisted store `localStorage['dframe-store']` in `state.collapsed` (bool) — a **global flag, not per-page**, which is why the script has to manage it across transitions. Buttons: when open it has `[aria-label="Collapse sidebar"]` (inside the aside); when collapsed it has `[aria-label="Open sidebar"]`. Don't touch `dframe-store` directly (React's store is already hydrated in memory; only clicking the button syncs the visible state). The note is saved per session in `localStorage` key `cc-notes:<sessionId>` (300ms debounce). Links become clickable (linkify). The editor is `contentEditable=plaintext-only` so a newline comes out as a literal `\n`. Linkify runs on `blur` (clicking away) and when opening/switching sessions — it does **not** run on `input`, on purpose (re-rendering on every keystroke would jump the caret / double the newline). `linkify` is an idempotent round-trip, so running it on blur is safe. Blur **only re-renders on a "real" blur** — `val !== lastRendered && document.hasFocus()` (v2.20). `lastRendered` is updated inside `setText`. The `document.hasFocus()` guard is the discriminator: `true` when focus goes to another element on the **same page** (then re-render to linkify); `false` when focus leaves the page (tab/window switch) — then it does **not** rewrite the `innerHTML`, so Chrome preserves the caret on return, **even after editing**. It's robust to tab-switch flakiness: if `blur` doesn't fire, the DOM stays intact too; if it does, the false `hasFocus()` skips the re-render. Cost: a freshly-typed URL only becomes a link on the next real blur / session switch. A re-render destroys the selection because it recreates the nodes; switching **sessions** still loses the caret (layer 2, not done). A **normal click** on a link **always** opens it in a **background tab** (`active:false`, doesn't switch tabs); **Cmd/Ctrl+click** opens **and focuses** (`active:true`). Both via `GM_openInTab` (`openTab`). There's no "not editing" guard: the editor is focused by default, so requiring `!editing` made a normal click do nothing (bug v2.11). Cost: to edit a link's text, place the caret outside it. Important: a synthetic modifier click on an `<a>` **was tested and does NOT open in the background** (it opens in the foreground) — that's why `GM_openInTab` and the `@grant`. The header shows `Notes (v…) · <chat name>` — version read from `GM_info.script.version` (single source) and the chat name from `button.cursor-text` (Claude's editable header, includes the `[id]` prefix; same source the favicon uses). The name is updated in `tick` via `syncName()` (follows session switches and renames); it only shows in a session. The `·` is its **own span** and the space on both sides comes from the flex container's `gap: 6px` (a space in the text doesn't work: a flex item drops leading whitespace and trailing whitespace is fragile). On home, `syncName` hides both the separator **and** the name with `display:none` (removes the gap too, with no leftover space after the badge). A long name truncates with an ellipsis (`text-overflow: ellipsis`) without pushing the toggle/`×`.

The **resize handle** (pill) is hidden (`opacity: 0`) and only appears on edge hover or during the drag (flags `gripHover`/`gripDrag` → `syncGrip`). It sits outside the card's (`col`) left edge via `marginLeft:-10px` on the `handle` (a sibling of `col` inside the transparent `drawer`) — landing in the 12px gap between the action bar/content and the panel. The drag math discounts the right inset: `nw = innerWidth - EDGE - clientX`.

DOM facts:
- `sessionId` comes from the path: `/session_[A-Za-z0-9]+/`.
- The bar the button is injected into is found via `button[aria-label="Share"|"Session actions"|"Diff"]`, climbing up to `span.epitaxy-titlebar-fade` (or its parent).
- The main content that's "pushed" by the panel is `main.dframe-content` (it adjusts `style.right`) — `squeeze()` tries the old id `#dframe-main` first and falls back to the new one. **App change (jul/2026):** Claude Code Web swapped the id `#dframe-main` for the class `<main class="dframe-content">` (same footprint `position:absolute; left:0; right:0`; setting `right` shrinks the width). Without the fallback the panel sat **on top of** the content instead of docking beside it (v2.23). Since v2.24 `squeeze()` reserves `w + RESERVE` instead of just `w`, to leave the floating panel's gap (`RESERVE = 8` since v2.26, measured to match the native 12px — detail above). The rest of the hooks (`aside.dframe-sidebar`, `dframe-store`, the `Open/Collapse sidebar` buttons) stayed the same.

## scripts/session-shortcuts.user.js
All keyboard shortcuts for Claude Code Web, in one file. (Formerly `session-switch-hotkey.user.js`, renamed for clarity once it had grown beyond the switch keys — the rename changes the filename **and** `@name`, so it's a one-time reinstall in Tampermonkey; delete the old "Switch Session Hotkey" entry by hand.) Minimal script: a single capture-phase `keydown`, no panel/observer.

**Bindings (all `Ctrl+Shift+*`, matching the app's own convention — the app uses Ctrl, not Cmd, even on Mac):**
- `Ctrl+Shift+[` (previous/up) and `Ctrl+Shift+]` (next/down) — switch the open session by walking the sidebar list.
- `Ctrl+Shift+S` — toggle the Session Notepad panel (clicks `[data-cc-notes-btn]`, the button the notepad injects).
- `Ctrl+Shift+R` — rename the open session.
- `Ctrl+Shift+C` — toggle the plan-usage panel.
- `Ctrl+Shift+B` — toggle Background tasks; `Ctrl+Shift+A` — toggle Artifacts (both are items of the ⋮ "Session actions" menu).

**Cross-platform behavior (the reason for the split):** the app uses `Ctrl+Shift+*` on **both** Mac and Windows — there's no Cmd→Ctrl translation, `Ctrl` is the same key on both. It runs cleanly on Mac because **Mac Chrome uses Cmd** for its own shortcuts, leaving `Ctrl+Shift` free. On **Windows/Linux, Chrome itself uses `Ctrl+Shift+*`**, and for the reserved window/tab/reload/DevTools combos a web page **cannot** override them with `preventDefault` (confirmed: reload `Ctrl+Shift+R` and DevTools `Ctrl+Shift+I/J/C` are unblockable). So:
- `Ctrl+Shift+[` / `]` and `Ctrl+Shift+S` are **not bound by Chrome** → enabled on **every platform**.
- `Ctrl+Shift+R` (=hard reload), `Ctrl+Shift+C` (=DevTools inspect), `Ctrl+Shift+B` (=bookmarks bar), `Ctrl+Shift+A` (=tab search) collide with reserved Chrome shortcuts on Win/Linux → gated behind `isMac`. On Windows those actions are reachable via on-screen UI (the notepad button, the ⋮ menu, the usage button). There is no universally-free modifier on Windows the way `Ctrl+Shift` is on Mac (Alt+Shift = keyboard-language switch; Ctrl+Alt = AltGr on international layouts), so alternate Windows bindings aren't worth the new conflicts.

**Rename** (`rename()`): clicking the title (`button.cursor-text` — the same source favicon/notepad use) opens the inline **name input**, focused with all text selected. Then `rename()` **repositions the selection** onto the leading "status token" so one keystroke swaps it:
- If the name starts with `[`, it selects the **text inside** the brackets — **without** the `[` `]` (e.g. `[ESPERAR VENDAS]` ⇒ selects `ESPERAR VENDAS`), via `setSelectionRange(1, indexOf(']'))`.
- Otherwise, if the name starts with a **status emoji followed by a space** (e.g. `🟣 Fixes` ⇒ selects `🟣`), it selects just that leading emoji. Emoji detection is robust: `firstGrapheme()` takes the first grapheme cluster (via `Intl.Segmenter`, so a colored circle / ZWJ sequence / flag counts as one) and `isEmoji()` tests it against `\p{Extended_Pictographic}`. It's gated on the emoji being followed by a space so it doesn't misfire on a normal first word (`Fixes …`) or a plain single letter (`A …`). `setSelectionRange` uses UTF-16 offsets, so `[0, grapheme.length]` covers the full surrogate pair.
- Otherwise, it leaves the full selection the rename opened with.

Notes on rename: synthetic key events **don't move the caret** (only OS-trusted events do), which is why it uses the **Selection API** directly instead of "sending arrow keys". The `<input>` appears async (React re-render), so it retries (`document.activeElement` is an INPUT with `selectionStart`) until it focuses; tested live that the selection **survives** the re-render. Tested: the synthetic `.click()` fires React's handler and opens the input; there is **no** native global shortcut (the `R` in the `⋮` menu is just the menu's accelerator, invalid when focus is elsewhere). **Only on Mac** (`isMac`), same reason as usage/panels below. **No focus guard, on purpose** — it works even while typing in the prompt/notepad (rename from anywhere is the goal).

**Usage** (`usage()`): toggles the plan-usage popover ("Plan usage / 5-hour limit / Weekly · all models / Usage credits"). It clicks the bottom-right button (next to "Opus 4.8"/effort), found by `button[aria-label^="Usage:"]` — the `aria-label` carries the `%` (e.g. `Usage: plan 46%`), hence the **prefix** match. The `.click()` is a **toggle** (same button opens and closes). It exists on home **and** in a session, so **no session guard**.

**Toggle notepad** (`toggleNotes()`): `document.querySelector('[data-cc-notes-btn]')?.click()` — clicks the button the notepad userscript injects into the action bar. Pure DOM, no cross-sandbox event. Only present in a session (where the notepad is used); a no-op on home.

**Background tasks / Artifacts** (`togglePanel(labelRe)`): **App change (jul/2026):** these two **stopped being direct buttons** in the action bar and became **items of the ⋮ "Session actions" menu** (`role="menuitemcheckbox"`). So the old `button[aria-label*="background task" i]` lookup stopped finding anything (the button no longer exists). Now both use a generic `togglePanel(labelRe)`: find the trigger `button[aria-label="Session actions"]`, open the menu (`.click()`), find the **visible item** by text (`^Background tasks$` / `^Artifacts$`, with `offsetParent` to pick the visible one, not a hidden residual) and click it — the `.click()` fires React's panel toggle. Then it **closes the menu**: the Radix `menuitemcheckbox` does **not** close the menu on select, so it re-clicks the trigger if it's still expanded.

DOM facts found by inspecting live (for `togglePanel`):
- **The menu's open/closed state = the trigger's `aria-expanded`.** There's a **persistent hidden `[role="menu"]`** in the DOM (Radix forceMount), so checking the menu's *existence* is misleading (it always looks "open"); `aria-expanded` reflects the real visual state.
- The **item is only mounted in the DOM while the menu is open** (it unmounts on close) — that's why `togglePanel` **polls with retry** after opening the menu, and `findItem` uses `offsetParent` to pick only the **visible** item.
- **Synthetic `Escape`/click-outside do NOT close** the Radix menu (it listens for real OS events); **re-clicking the trigger** closes it reliably. (Tested: `dispatchEvent(KeyboardEvent Escape)` and an outside `PointerEvent/MouseEvent` don't take.)
- A direct click on a hidden `menuitemcheckbox` **also** fires the toggle (React), but only while it's still mounted from a recent open — not reliable as the main path, hence always opening the menu first.

Sidebar DOM facts (found by inspecting the page) that the script depends on:
- The sidebar mixes **menu items** and **sessions**, both with `[data-row]`. Menu items (New session, Routines, Customize, More) are `<button data-row>` (the row itself is the button, no inner button). **Sessions** are `<div data-row>` with a `<button data-row-main-button>` inside — that main-button is the clickable one that navigates. So sessions = `div[data-row]` that has the main-button.
- The row order in the DOM = the visual order, crossing the groups (Pinned/Developing/Ideas/Waiting/In Review) top to bottom. `go(±1)` walks that flattened list.
- **Open session (anchor):** the open row carries `data-selected` (value `"focused"`, sometimes `"open"` — see the classes `data-[selected=focused]` / `data-[selected=open]`). It's **only one** at a time and follows the route — confirmed on a fresh page load and after each switch. On home no **session** row has `data-selected` (the roving focus sits on `New session`, which is a menu button) → `currentIdx` = -1, so `]` opens the first / `[` opens the last.
- **Navigates via `.click()` on the main-button** (fires React's router). **Works with the sidebar COLLAPSED** (28px): the rows stay in the DOM, keep `data-selected` and a real rect; the synthetic click ignores the visual clipping. This matters because the notepad collapses the sidebar in session mode.
- **Key:** use `e.code` (`BracketLeft`/`BracketRight`, physical key) and **not** `e.key` — with Shift, `[` / `]` report as `{` / `}`, but `e.code` stays Bracket*. The handler requires exactly `ctrlKey && shiftKey` (no meta/alt).
- Accepted limitation: sessions not in the DOM (a collapsed group / virtualization with a very long list) fall outside the cycle. For the current lists (~10-15) they're all rendered.

## Testing/linting
- Not a Node project; no build. Manual editing of the `.user.js`.
- Quick syntax check: `node --check scripts/<file>.user.js`.
- Optional lint with ESLint (flat config), formatting rules + `no-undef` with browser globals. Globals used: `window, document, location, navigator, localStorage, history, setTimeout, setInterval, clearTimeout, MutationObserver, Image, Intl, addEventListener, Promise`. The notepad also uses `GM_openInTab` and `GM_info` (Tampermonkey).
